## Root cause of the Stripe gap
`backend/core.py:709` → `stripe.api_key = os.environ.get("STRIPE_API_KEY", "")` and `routes_stripe.py:105` → `os.environ.get("STRIPE_WEBHOOK_SECRET", "")`.

- In **preview**, `STRIPE_API_KEY` is supplied by the agent-env **pod environment**, so Stripe works there.
- Production secrets are copied from the **`.env` files**, NOT from the live pod environment. `backend/.env` in the built snapshot contains only: MONGO_URL, DB_NAME, CORS_ORIGINS, FRONTEND_URL, JWT_SECRET, ADMIN_EMAIL, EMERGENT_LLM_KEY, EMERGENT_EMAIL_KEY, EMAIL_FROM_NAME, WEBHOOK_CRON_SECRET. **No STRIPE_* keys.**
- Production secret store (active run) has 16 keys; **`STRIPE_API_KEY` / `STRIPE_WEBHOOK_SECRET` are absent.**
- Net effect: `stripe.api_key` is `""` in production → all payouts/Connect onboarding calls fail. The Disbursements *page* renders (frontend is deployed) but its Stripe operations are non-functional.

## Fix path
1. **Add the Stripe secrets so they reach production.** These are NEW keys (not currently in the production secret store), and the Secrets UI can only edit existing keys — so they must be written into `backend/.env` in the preview workspace and then a **redeploy** performed (new `.env` keys are picked up on redeploy). Add `STRIPE_API_KEY` (live/secret key) and `STRIPE_WEBHOOK_SECRET` if webhooks are used. Redeploy after adding.
2. **The non-Stripe "missing" features are already live.** They compiled into the served bundle (`main.61548271.js`). If they still appear absent in the browser, that is client-side cache — hard-refresh / open in incognito to confirm; no redeploy is needed for those.

## What is NOT the problem
- Not a stale build, not a stuck/failed deploy, not a CDN/KV pointer serving old assets, not an old workspace snapshot. reportlab and its Pillow dependency are present and installed.
